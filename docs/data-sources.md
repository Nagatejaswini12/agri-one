# External Data Sources

No module may fabricate live data. If a source below is unconfigured or
fails, the module must return/render an "unavailable" state.

| Module | Source | Notes |
|---|---|---|
| Weather | **Open-Meteo** (live, no key) | Queried with the farm's own `farms.latitude/longitude` — never a default location. Current conditions + 3-day forecast, `timezone=auto`. "Current" means the source's latest reading, not a guaranteed real-time observation. Chosen over OpenWeatherMap because it needs no credential; `OPENWEATHERMAP_API_KEY` stays unused. IMD if/when freely accessible. |
| Market | AGMARKNET via data.gov.in (resource `9ef84268-d588-465a-a308-a864a43d0070`) | **Live.** Requires a free data.gov.in API key, held as an n8n Credential (HTTP Query Auth), never in `.env` or the repo. A daily snapshot, published with lag (often 1+ day) — the UI shows the source's own `reportedOn` date prominently and `asOf` separately, current prices only, no trend charts. Every reporting mandi is shown; a price the source omitted renders as "—", never 0. The farm's state/district are resolved onto AGMARKNET's own spellings exactly or not at all — an unmatched district returns "unavailable" naming what was searched for. |
| Soil | Farmer-entered values / Soil Health Card upload | No public API; this is inherently real because it's farmer-provided. |
| Pest | Pest/disease knowledge base + regional advisories where available | Falls back to general seasonal guidance, clearly labeled as such if no live regional alert exists. |
| Government Schemes | Curated catalog built from official portals (pmkisan.gov.in, pmfby.gov.in, soilhealth.dac.gov.in, agriinfra.dac.gov.in, pmkusum.mnre.gov.in, myscheme.gov.in, and state department sites) | **Live, and deliberately not an API.** There is no public source for Indian scheme eligibility: myScheme's own endpoint (`api.myscheme.gov.in/search/v4/schemes`) returns 401 to anything outside its portal, and data.gov.in publishes scheme budget/beneficiary tables rather than eligibility rules. So the catalog is human-curated inside `Schemes - Core`, each entry carrying `sourceName`, `sourceUrl` and `lastVerifiedOn`, and the UI shows all three. Never generated by an LLM and never derived from the request. `Schemes Catalog Check` re-tests every source URL weekly and flags stale entries, but **reports only** — a person re-reads the page and updates the entry. The result is a discovery list, never an eligibility verdict. |
| Crop Diagnosis | Roboflow Serverless Hosted API, model `crop-disease-axhjj/1` | Only runs on farmer-uploaded images; low-confidence, empty, unsupported, or ambiguous results return `category: "inconclusive"`, never a guessed label. **Prototype scope**: 9 classes, tomato-focused — not comprehensive crop coverage, and not a guaranteed agricultural diagnosis. |
| Translation / Voice | **Browser-native (Web Speech API)** for v1 — no key, no cost, no server dependency | **Live.** Speech recognition where the browser supports it (Chrome/Edge/Safari; not Firefox by default) and `speechSynthesis` for output; Indic voice availability varies by device, so both are feature-detected and the assistant degrades to text with a visible notice rather than silence. Text answers are translated by `react-i18next` from the locale bundles, never by a service. Bhashini (free for non-commercial, needs userId + ulcaApiKey + inference key) or Sarvam remain the upgrade path behind the existing `SpeechProvider` interface — neither is wired yet. |
| Reports | Farmer-entered cost/revenue and harvest records | **Live.** No external source and no API key: every figure is typed by the farmer. Totals are arithmetic over stored rows only — no entries renders an empty state rather than ₹0, and yields are grouped per unit because different units cannot be added. |
| Buyers / Marketplace | **No known open verified dataset** — so none is shown | This remains the largest data-availability risk, and the Marketplace module is built around admitting it. "Where you can sell" reuses the same AGMARKNET snapshot as Market and shows **the mandis that reported a price**, which is a different fact from who will buy: the page says so in its opening disclaimer and again in a closing "AGRI ONE holds no trader contacts and does not arrange sales". No buyer name, phone number, trader contact or private party data appears anywhere in the module, and none is fabricated to fill the gap. Venue type is read only from the source's own mandi naming (`Uzhavar Sandhai` → farmers' market, `APMC` → regulated yard, otherwise a plain market label) — never inferred. Venues are grouped by variety and ranked **only within a variety**, because AGMARKNET prices for different varieties of one commodity are not comparable. Official selling channels are shown only where the curated scheme catalog holds a verified entry for that farm's state, mirrored by `catalogId` with the URL, source name and verification date asserted against the catalog in tests; a state with no verified channel gets no section rather than a national placeholder. A real buyer directory would need manual curation or a partner feed. |

All API keys live in `.env` files (see `.env.example` at the repo root
and in `services/n8n/`), never committed, never referenced from
`apps/web` directly.
